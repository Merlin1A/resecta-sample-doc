# search-ground-truth — rebaseline log

The frozen sidecars (`*.search-gt.json`) change only through a row here, the
rebaseline rule Chromium's layout tests follow. Every row answers *what changed, why, and which
kind of change it was* — `initial` (the first freeze), `bug-fix` (the old
expectation was wrong), `intentional` (engine behavior legitimately changed;
cells rebaselined), or `regenerated` (OCR-leg expectations are
tool-regenerated by definition — Vision output is not stable across OS
versions and is never hand-edited).

Sidecar provenance: `search-queries.json` (the query bank) is generated by
`tools/build_search_queries.py`; the frozen GT is emitted by
`tools/search_oracle.py freeze` from an official run of the app's search
harness plus the adjudication file (`adjudication-p15.json`). Hand-editing a
sidecar is a process violation.
